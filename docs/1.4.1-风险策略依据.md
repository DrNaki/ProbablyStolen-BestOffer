# 1.4.1 自动禁卖策略依据

本次仅对本地单机游戏 `Probably Stolen Demo` 的原生交易实现作静态核对；没有修改游戏原始程序或存档，也没有读取未鉴定属性来判定风险。

目标 `GameAssembly.dll`：Windows x64 Unity IL2CPP，SHA-256 为 `3BEA17EEEC77ADAB6418918C28A8AA9A06F290582A2972639A48BD7E5A01AB44`。以下 RVA 对应该文件，方法名称和字段来自其 IL2CPP metadata，行为由原生指令交叉核对。

| 原生接口或字段 | 位置 | 核对结果 |
| --- | --- | --- |
| `ContrabandHelper.IsContraband(GameItem)` | RVA `0x8AEC90` | 仅检查物品的 `CONTRABAND_ITEM_TAG` 标签。 |
| `StolenHelper.IsStolenItem(GameItem)` | RVA `0x50F5C0` | 仅检查物品的 `STOLEN_TAG` 标签。 |
| `ContrabandHelper.CreateContrabandItemTooltip` | RVA `0x8AD1F0` | 用相同公开标签生成游戏原生违禁提示，没有 `ItemFeature.IsExposed` 鉴定条件。 |
| `StolenHelper.CreateStolenItemTooltip` | RVA `0x50ECE0` | 用相同公开标签生成游戏原生赃物提示，没有属性鉴定条件。 |
| `StoreClient.clientBuyingIdList` | 字段偏移 `0x50` | 买家明确收购的物品标识，和 `GameItem.identifier` 精确匹配。 |
| `StoreClient.clientBuyingTagList` | 字段偏移 `0x48` | 买家收购的标签，通过原生 `GameItem.IsTag` 匹配。 |
| `StoreClient.IsClientBuyingThisItem` | RVA `0x68BBA0` | 合并拒收检查、泛收、指定 ID、指定标签及自定义收购谓词；不能整体视为明确需求。 |
| `GameItem.AddClientItemBuyingFeature` | RVA `0x790B80` | 将 `clientItemFeatureBuying` 的条目作为价格特征工厂调用；这个列表不是物品需求。 |

原生例证：矿工工厂 `StoreClientList.CreateMiner`（RVA `0x5C7630`）向需求标签列表添加 `SUBSTANCE`；经销商工厂 `StoreClientListCartel.CreateDealer`（RVA `0x5F8A60`）添加 `NARCOTIC`。`GameItem.IsTag`（RVA `0x798130`）委托给 `TagSystem.IsTag`，不等同于 `itemTypes.Contains`。

「分类规则」中，违禁品与赃物分别设置“禁卖所有……”和“买家明确需要时允许出售”。例外只允许**明确的物品 ID 或具体需求标签**匹配，并且仅影响所在类别。泛收标签 `ALL_TYPE` 和 `ALL_TYPE_EXCEPT_CONTRABAND` 不授予例外；`AcceptingContrabandOverride`、价格修正特征、单纯“买家愿意收”也不授予例外。只有可以正常交易的当前买家参与需求判断；无买家时仍可配置，不能利用例外交易。无法由这些公开字段确认的自定义需求保持禁卖保护。

两类禁卖和各自的需求例外是四个独立选项，默认关闭，确保读取 1.4.0 的 JSON 设置时保留此前行为。商品同时属于两类时，任一类别仍受保护就继续禁卖。关闭类别保护后不会清除任何手工禁卖规则；开启例外也不覆盖手工禁卖。必卖与自动保护冲突时，原有必卖验证明确拒绝计算，不会悄悄删掉必卖物品。

整件出售容器时，容器本体及全部随售后代分别判断风险和各自需求。买家需要箱子，不代表需要箱中违禁物；任一后代被保护，整件容器就排除。展开后可独立取出的内容继续逐件检查，本体不参与整件出售。界面使用概括性“自动禁卖保护”，不显示隐藏内容名称、具体风险类别或未鉴定属性。

执行方案时，在每件移动前、原生摆放回调之后、实际卖出之前重新检查当前需求与全部随售内容；全部摆放结束后也再次检查台上方案。若回调撤销需求或增加受保护内容，停止后续操作，说明已经摆放或成交的进度；尚未成交的已摆物品保留在台上。这些检查不重复报价，也不调用 `GetUniqueID` 或写入物品身份。

纯逻辑由 `RiskPolicy.cs` 实现，测试覆盖两类保护与各自例外的全部组合、双重风险、泛收与明确需求区分、容器混合需求、手工禁卖优先、必卖冲突及旧 JSON 兼容；另用动态事实模型验证摆放或成交回调撤销需求、容器内容变化时的停止边界和进度。构建脚本强制运行该测试项目。
