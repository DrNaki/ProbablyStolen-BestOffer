## 实机结果

游戏启动、点击、按键及截图均使用 **cua-driver**。游戏为 Unity 自绘界面，UIA 未提供可操作控件，因此依据窗口截图定位，并在后台输入无效后使用前台输入。结果以实际截图、配置读回和运行日志核对。

| 场景 | 结果与证据 |
| --- | --- |
| 管理器增加配置 | 最佳报价显示面板、只读诊断两项热键；旧版无效交易选项不再显示。原始截图 01（`01-manager-hotkeys.png`，仅本地历史证据） |
| 管理器改键后应用 | 将面板设为 Ctrl+F11、诊断设为 Alt+F11，点击应用后写入 JSON，进入游戏可使用新按键打开面板。 |
| 交易设置改键 | 将面板改为 Shift+F11、诊断改回 F9，显示和保存均正确；改键按下的按键不会同时关闭面板。原始截图 02（`02-trade-hotkeys.png`，仅本地历史证据） |
| 双向同步 | 交易设置修改后重新打开管理器，缓存的两行立即显示 Shift+F11 / F9；管理器恢复 F8 后，交易设置立即显示 F8。原始截图 04（`04-native-to-manager-sync.png`，仅本地历史证据） |
| 重复绑定 | 面板尝试绑定已有诊断键 F9 时保持捕获，提示不能相同，原绑定保留。原始截图 03（`03-duplicate-protection.png`，仅本地历史证据） |
| Esc 取消 | 取消后仍停留在交易设置，原绑定保留；不继续关闭面板。 |
| 新旧按键区分 | 修改后旧 F8、单独 F11 不再触发；Ctrl+F11、Shift+F11 可开关面板。 |
| 重启保存 | 多次退出并重新启动游戏，启动日志和管理器保留上一轮保存的自定义快捷键。 |
| 只读诊断 | 面板打开时 F9 / 自定义 Alt+F11 能导出诊断；最终运行中一次 F9 仅产生一条导出日志。 |
| 恢复与保护 | 最后通过管理器恢复 F8/F9，全部原设置逐字段比较无差异；5 个 ES3 存档文件的 SHA256 全部不变。配置与哈希读回保存在本地证据目录。 |

实机范围为快捷键、设置同步和输入隔离，未进行交易成交操作。
