# 最佳报价 / Best Offer

为《深空当铺 / Probably Stolen Demo》增加报价配置、自动选货和确认出售功能。**版本 1.4.1** 使用游戏原生字体、平板素材和界面控件，入口位于交易 iPad 底部。

- **齿轮「报价配置」／F8**：提前设置库存规则、风险禁卖和交易选项。
- **货箱「一键摆货」**：按当前规则计算最佳方案并放到交易台，核对后再成交。
- **同名商品一起设置**：默认全部，支持指定数量，也可查看单件。
- **违禁品／赃物自动禁卖**：可允许买家明确需求的物品参与报价，手动禁卖始终有效。

详细操作见 [1.4.1 使用说明](docs/1.4.1-使用说明.md)。

适配环境：Windows x64，Demo `049-Rev5-L`，Steam build `25382790`，Unity `2021.3.45f2`，MelonLoader `0.7.3`。游戏更新后需重新确认兼容性。

## 游戏内使用

1. 进入店铺，按 **F8** 或点击 iPad 的 **报价配置**。
2. 在 **库存规则** 中设置必卖／禁卖。没有买家时也能配置；商品为灰色，价格显示「待报价」。
3. 在 **分类规则** 中分别设置 **禁卖所有违禁品**、**禁卖所有赃物**，以及各自的 **买家明确需要时，允许出售违禁品／赃物** 选项；选中时带 **✓**。
4. 在 **交易设置** 中选择货源、超预算清货上限和快捷键。百分比与固定信用点的当前选择均带 **✓**。
5. 买家到来后，点击 **计算最佳报价**，选择方案，点击 **摆上交易台**。也可关闭面板，直接点 iPad 的 **一键摆货**。
6. 核对游戏报价后用原生按钮成交，或在 **报价方案** 中点击 **按此方案卖出 → 确认卖出此方案**。

**F8**、**Esc** 或右上角 **×** 关闭面板。报价和摆货仅在可交易的买家到来、剧情或对话锁定解除后开放；等待期间库存规则仍可编辑。规则与选项自动保存。

### 数量与单件规则

同一显示名称合并为一行。例如有 10 件净水药片，点击 **禁卖** 就能保留整组；改成数量 3，会保留 3 件。数量可用 **− / +**、数字框或 **全部** 调整。再次点击已经符合当前数量的规则按钮，会取消这类规则。

批量操作保留同组已有的相反规则。例如已有 1 件必卖时，整组禁卖会保留它，并禁卖其余 9 件。需修改那件时，先取消必卖。**查看单件** 用于区分具体物品；单件与数量操作共用规则，按稳定物品 ID 保存。

手动数量规则只作用于当前货源范围内已有的物品；后来新买到的同名物品需重新设置。自动违禁品／赃物禁卖会持续作用于该类别，不需要为新增物品重复勾选。

### 自动禁卖与需求放行

页面顺序是 **库存规则 → 分类规则 → 报价方案 → 交易设置**。在 **分类规则** 中，违禁品和赃物各占一行，**禁卖所有违禁品**、**禁卖所有赃物** 分别禁止对应类别参与自动报价与摆货。新选项默认关闭，按需启用。页面上方显示本次自动排除的数量；库存页的 **禁卖** 筛选同时包含手动禁卖和自动禁卖物品。

每一行的 **买家明确需要时，允许出售违禁品／赃物** 只解除按钮写明类别的自动禁卖，两类可分别选择。关闭本类禁卖时，其需求选项变灰并保留原选择。买家必须明确请求该物品或其类别；「什么都收」、仅允许买违禁品、价格加成，都不算明确需求。买家不收货、需要鉴定、预算与种类限制仍然生效。

**手动禁卖始终保留**，需求放行不会覆盖它。必卖物品被自动保护或买家拒收时，计算会提示原因；调整必卖、自动禁卖或需求例外后重新计算。整箱出售时检查箱内各物品；买家需要箱子，不会因此放行箱内受保护的物品。

库存页的 **清除手动规则** 清除当前货源范围内物品及其容器内容的手动规则，保留分类规则中的禁卖与需求例外设置。

### 货源与超预算清货

库存、交易台和柜台参与报价；展示柜、隐藏仓库可分别选择。**储藏箱内容** 开启后，可独立完整取出的内容物单独参与，展开的箱体保留；关闭时箱子连同内容整体报价，内容物禁卖会保护整箱。锁定部件或只能部分取出的堆叠不会强拆。

超预算清货默认关闭。开启后可选择 **百分比 %** 或 **固定信用点**，输入允许超出的上限。买家预算 100、上限 10% 时，名义总价可到 110，实际最多收 100，另 10 放弃收取。确认出售前会列出该金额。超预算方案通过 Mod 的两次确认出售；原生成交按钮仍可能按游戏预算限制拒绝。

方案按实收最多、少收金额最少、件数较少排序。库存、买家、预算、价格或选项改变后需重新计算。搜索触及上限时会提示「搜索未完成」。

## 安装、更新与卸载

先退出游戏，在项目或安装包根目录打开 PowerShell：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Install.ps1
```

默认游戏目录是 `E:\Steam\steamapps\common\Probably Stolen Demo`；其他位置加 `-GameDir '游戏目录的完整路径'`。通过 Steam 正常启动游戏。MelonLoader 首次启动会生成 IL2CPP 互操作程序集，需要更长时间；运行依赖 Windows x64 .NET 6 Runtime。

安装器会校验现有 DLL、安装记录及加载器；遇到未知同名文件会停止并给出路径。模组管理器中的启用／禁用状态在更新时保留，应用启用状态后重启游戏。

卸载最佳报价，保留加载器、规则、设置和存档：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Uninstall.ps1
```

需要同时移除本安装器记录且校验一致的加载器文件时，添加 `-RemoveLoader`。日志与生成缓存保留。

## 回滚到本轮保留的 1.4.0

退出游戏后，恢复 1.4.0 DLL／PDB，保留当前规则、设置与存档：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Rollback.ps1
```

默认基线是 `BestOffer-1.4.0.zip`，SHA256 为 `774BD3C870AF4A77B4484BDD416F81A93D30E0435D235C7EA123110D6BDB4ECE`。脚本先校验并备份当前文件，再替换已确认属于本 Mod 的文件。

如需精确恢复本轮修改前的最佳报价、配套仓库整理，以及当时的规则和设置，使用本机检查点：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\backups\before-1.4.1-20261013-104025\Restore-BestOffer-1.4.0.ps1 -VerifyOnly
powershell -NoProfile -ExecutionPolicy Bypass -File .\backups\before-1.4.1-20261013-104025\Restore-BestOffer-1.4.0.ps1
```

`-KeepCurrentSettings` 保留当前规则及两个 Mod 的设置；`-BestOfferOnly` 只恢复最佳报价。检查点恢复不会写入游戏存档。详细说明见 [回滚与存档保护](backups/before-1.4.1-20261013-104025/回滚与存档保护.md)。

源码由 Git 的 **v1.4.0** 标签保留。先保存当前未提交修改，再创建独立回退分支：

```powershell
git switch -c restore-1.4.0 v1.4.0
```

Git 切换只改变源码；游戏里的版本通过回滚脚本恢复。

## 构建与排查

安装 .NET 8 SDK，游戏通过加载器启动一次生成互操作程序集后，在项目根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build.ps1 -Reproducible
```

构建先运行报价求解器、同名数量规则和风险保护测试，再输出 `dist/BestOffer.dll`。构建不会自动安装，也无需改动原版 `GameAssembly.dll` 或游戏资源。

| 提示 | 处理 |
|---|---|
| 等待买家／当前不可交易 | 先配置库存规则，等待普通买家与剧情锁定解除 |
| 必卖物品被自动禁卖保护 | 调整对应自动禁卖或必卖；有明确需求时可开启需求放行 |
| 必卖条件无法满足 | 检查买家需求、预算、种类限制与货源范围 |
| 容器规则冲突 | 展开容器内容独立选择，或调整必卖／禁卖 |
| 交易台有未选物品 | 将未选物品移回库存，再计算 |
| 台面放不下 | 腾出台面，或选择 Mod 的逐件确认出售 |
| 搜索未完成 | 缩小候选范围后重试 |

操作中断会报告已经移动或成交的数量。**一键摆货** 只移动商品；Mod 出售的第一次点击只展示确认文字，第二次才成交。

配置位于游戏目录的 `UserData/BestOffer-rules.json` 与 `UserData/BestOffer-settings.json`。按 **F9** 可生成只读诊断，最近报价记录为 `UserData/BestOffer-last-quote.json`，日志为 `MelonLoader/Latest.log`。快捷键可在交易设置中修改，避免与其他 Mod 重复。
