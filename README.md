# 最佳报价 / Best Offer

为《深空当铺 / Probably Stolen Demo》增加自动选货功能：计算最佳出售组合、指定必卖和禁卖，并选择容器范围与清货上限。**当前版本 1.4.0** 将入口加入交易 iPad，使用游戏原生 uGUI、简体中文字体与平板图像，重构为「库存规则」「报价方案」「交易设置」三个页面。同名商品默认一起设置，也可按数量或查看单件处理。旧发布包保留在 `release/`。

完整操作与当前验证进度见 [1.4.0 使用说明](docs/1.4.0-使用说明.md)。

适配版本：Windows x64，Demo `049-Rev5-L`，Steam build `25382790`，Unity `2021.3.45f2`。基于 MelonLoader `0.7.3`。游戏更新后可能需要重新适配。

## 在游戏里使用

1. 载入存档，进入店铺，等待一位买家到来。
2. 点击交易 iPad 底部的 **最佳报价**，或按 **F8**。
3. 在 **交易设置** 中选择报价范围：**展示柜**、**隐藏仓库**、**储藏箱内容**，修改自动保存。开启储藏箱内容后，可取出的物品单独参与筛选，已展开的箱体保留。
4. 在 **库存规则** 中，对需要保留的同名商品选 **禁卖**，对这次一定要卖的商品选 **必卖**。默认选择全部；需要只处理部分时，用 **− / +** 调整数量或直接点击数量框输入。然后点击 **计算最佳报价**。
5. 在 **报价方案** 中选择方案，点击 **摆上交易台**，检查游戏报价后用游戏原有按钮成交；也可以点击 **按此方案卖出**，再点 **确认卖出此方案**，自动逐件成交。
6. 按 **F8** 或 **Esc** 关闭面板。

## 同名商品与数量规则

同一显示名称的商品合并为一行，不需要逐件勾选。例如当前有 10 件净水药片，点击这一行的 **禁卖**，即可一起保留这些药片。用 **− / +** 指定件数，也可点击数量框直接输入正整数，或点击 **全部** 恢复全量选择；数量限制在 1 到组总件数。只有一类规则已启用时，调整数量会更新它；两类规则同时存在时，调整最近操作且仍存在的那类规则。把禁卖从 10 件改为 3 件，会取消另外 7 件的禁卖。再次点击已符合当前数量的规则可取消该规则。

数量调整保留同组已有的相反规则。例如 10 件中已有 1 件必卖，设置全部禁卖时会保留那件必卖，只禁卖另外 9 件，状态文字会说明保留数量。需要改掉那件必卖时，先取消它的必卖。减少数量时优先保留已经选中的个体，再按稳定物品 ID 选择，库存摆放顺序变化不会随机更换选中的商品。

点击 **查看单件** 可查看每件商品的报价与所在货源；可卖商品显示游戏已经鉴定、公开的原生特征，不可卖商品显示原因，再单独指定必卖或禁卖。不会额外鉴定或揭示隐藏属性。单件与同名数量操作使用同一份规则。

批量操作只作用于当前报价范围内、当前已有的同名物品。规则仍按存档运行 ID 与物品唯一 ID 保存，兼容原来的 `BestOffer-rules.json`，重新打开游戏仍有效；**之后新买到的同名商品不会自动加入禁卖或必卖**，请重新设置。数量按可独立处理的物品件数计算，不能完整取出的堆叠不会强行拆分。

容器内容物的原有规则仍受保护：箱子连同内容一起出售时，内部禁卖会保护整个箱子；箱子或内容同时产生必卖、禁卖要求时，计算会提示冲突。**清除当前规则** 会清除当前范围物品及其容器内容物的规则，请在需要重新设置这一范围时使用。

## 交易设置与快捷键

在 **交易设置** 中修改货源范围、允许超预算、上限单位与数值，也可修改面板／诊断快捷键（功能键，可带 Ctrl/Alt/Shift）。配置自动保存，无需重启。F5/F6 已用于第三方 Mod，F7/Shift+F7 默认用于仓库整理，改键时请避免重复。

两个入口随交易 iPad 显示，设置和选货共用平板页面。模组管理器仍可启用／禁用本 Mod；应用启用状态后需重启游戏。

配置和快捷键保存在 `UserData/BestOffer-settings.json`；旧版本保存的按钮位置字段可继续保留，1.4.0 的位置由交易 iPad 布局决定。1.3.0 已将管理器中应用过的设置同步到 JSON，升级后继续使用这些值；旧的 `[BestOffer]` 偏好段不再控制本 Mod。管理器可以移除，自制 Mod 本身不依赖其 DLL 来加载。

安装、回退、卸载脚本会识别管理器移到 `Mods/Disabled/` 的 DLL；更新与回退会保留禁用状态，同时存在启用／禁用两个副本时会拒绝覆盖。

## 一键摆货

设置好偏好后，关闭面板，点击交易 iPad 底部、**最佳报价** 旁的 **一键摆货**。无需打开面板或再点计算：它会根据当前的货源范围、必卖／禁卖和超预算设置，计算一个最佳方案，把方案内的全部商品放到交易台。

这个按钮只摆货，**不会成交或改变现金**。如果有多个并列最佳方案，会使用其中一个；想手动比较时仍可打开原来的面板。提示在交易 iPad 顶部标题栏；完整结果/失败原因可按 F8 查看。计算期间显示“正在计算”；按 Esc 或打开面板可取消尚未完成的计算。

如果方案超出买家预算，仍可按已设置的清货上限摆货，按 **F8** 查看预计实收与少收金额；要实际出售，请在面板内重新计算并确认清货。台面上已有未选中的物品时，会要求先移回库存；台面空间不足时，会说明已移动的数量，不会改为自动出售。

库存商品组、单件详情、方案列表与商品明细都有翻页按钮。计算只读取报价，不会自动卖出。范围和清货设置也会保存。

## 允许超预算清货

默认关闭。在 **交易设置 → 超预算清货** 中开启 **允许超预算**，选择 **百分比 %** 或 **固定信用点**，点击数字框输入上限；Ctrl+A 全选，Enter 完成，修改自动保存。金额计算使用十进制数，实际允许的信用点仍向下取整。

例如买家剩余预算 100：

- 设置 **10%**，允许商品名义总价最高 110。
- 设置 **固定 25 信用点**，允许商品名义总价最高 125。
- 售出名义价 110 的方案时，**实际只收 100，另外 10 不收取**。不会增加买家预算，也不会补发差额。

百分比以当前剩余预算为基数，允许超出的信用点向下取整。界面同时显示名义总价、预计实收和不收取金额。方案按 **实收最多 → 不收取金额最少 → 件数较少** 排序，避免为了相同收益多送商品；你仍可以选择较低排名的清货方案。需要清掉指定商品时配合 **必卖** 使用。

超预算方案可以通过 **一键摆货** 或 **摆上交易台** 先放到台面。实际清货使用 Mod 的 **按此方案卖出 → 确认卖出此方案**，确认文字会列出放弃收取的金额；游戏原有按钮可能按预算限制拒绝成交。关闭清货选项后恢复严格预算模式。

## 报价范围

- 使用当前买家的实际购买偏好、剩余预算、种类限制、已完成议价、市场事件与原生报价规则。
- 包括库存、交易台、柜台、展示柜与隐藏仓库中可读取的自有物品。买家不收、需要鉴定、被锁定或单件超预算的物品会显示原因。
- **储藏箱内容关闭**：容器与内容按整件计算，内部已有禁卖规则会保护整个容器。
- **储藏箱内容开启**：容器内可完整、独立取出的自有物品单独参与报价；展开的容器本体不会出售。不能移动的内建部件、锁定内容或只能部分取出的堆叠不强拆，无法展开的物品仍按整体处理。
- 展示柜与隐藏仓库可以分别排除。若排除了某个仍存在的必卖物品所在范围，计算会提示调整范围或取消必卖，不会悄悄忽略该条件。
- “最高”指当前库存与当前交易条件下的最高总报价；不会替你进行带随机结果的议价或改变买家预算。
- 显示最多 12 个方案，可能同时包含并列最优方案和其他备选方案。
- 库存、顾客、预算或价格变化后，旧方案作废，需要重新计算。复杂库存触及搜索上限时会显示“搜索未完成”，不会把近似结果标成最优。

## 安装、更新、回退和卸载

当前电脑由本项目直接安装。重新安装时先退出游戏，在本文件所在目录打开 PowerShell：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Install.ps1
```

默认游戏目录为 `E:\Steam\steamapps\common\Probably Stolen Demo`。其他位置使用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Install.ps1 -GameDir 'D:\SteamLibrary\steamapps\common\Probably Stolen Demo'
```

通过 Steam 正常启动游戏。首次安装加载器后会生成 IL2CPP 互操作程序集，启动需要更久；本机已经生成。运行需要 Windows x64 .NET 6 Runtime，本机已安装。若安装器发现其他版本的加载器或未知同名 Mod，会停止并给出具体路径。

**默认回退到重构前的 1.3.1**：退出游戏，在本文件所在目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Rollback.ps1
```

1.4.0 安装包自带经过 SHA256 校验的 `rollback\BestOffer-1.3.1.zip`，本项目也保留 `release\BestOffer-1.3.1.zip`。回退脚本校验旧包，备份当前版本，恢复旧 DLL/PDB 并更新安装记录；游戏存档、当前禁卖／必卖规则和交易设置都会保留。也可以明确指定 1.3.1：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Rollback.ps1 -ReleaseZip '.\release\BestOffer-1.3.1.zip'
```

如需精确恢复本次修改前实际安装的 1.3.1 及当时的规则、设置，本机另有完整检查点 `backups\native-ui-before-1.4.0-20261012-153523`。退出游戏后，从项目根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\backups\native-ui-before-1.4.0-20261012-153523\Restore-BestOffer-1.3.1.ps1 -VerifyOnly
powershell -NoProfile -ExecutionPolicy Bypass -File .\backups\native-ui-before-1.4.0-20261012-153523\Restore-BestOffer-1.3.1.ps1
```

检查点恢复脚本会先备份当前文件，再校验并恢复旧 DLL、PDB、安装清单与当时的规则和设置；加 `-KeepCurrentSettings` 可保留当前规则和设置。此脚本不恢复或改写游戏存档。检查点内还保存修改前的源码、构建脚本、发布包与完整存档目录，开发源码可从其中取回。想重新升级时，再运行当前目录的 `Install.ps1`。

更早的 1.0.0、1.1.0 等发布包仍保留在 `release/`，需要时可通过 `Rollback.ps1 -ReleaseZip '旧包的完整路径'` 指定。

卸载本 Mod，保留加载器、配置和存档：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Uninstall.ps1
```

同时移除本安装器记录且校验一致的加载器文件：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Uninstall.ps1 -RemoveLoader
```

卸载不会删除游戏存档。加载器生成的缓存和日志保留，不影响原版游戏启动。

## 遇到提示时

| 提示或现象 | 处理方式 |
|---|---|
| 请进入店铺并等待买家 | 在普通买家到店后打开；出售物品给你的顾客不能作为买家报价 |
| 必卖条件无法满足 | 检查该买家是否收这种货、必卖总价是否超过预算、种类限制是否冲突 |
| 容器同时包含必卖和禁卖物品 | 开启储藏箱内容单独选择，或调整冲突规则 |
| 必卖物品在未包含范围 | 勾选对应范围，或取消该件物品的必卖规则 |
| 已展开容器本体不能必卖 | 若要卖整个箱子，关闭储藏箱内容，再重新计算 |
| 交易台有未选物品 | 先把台上物品移回库存，再计算和应用 |
| 台面放不下 | 清出台面；也可以选择自动逐件卖出 |
| 实际报价与预览不同 | 特殊事件或商品回调改变了价格；查看台面并重新计算 |
| 搜索未完成 | 缩小可卖范围后重试；不会出售任何东西 |

操作中断时，提示会说明已经移动或成交的数量。已经放到台上的商品留在台上，已成交商品不会伪装成回滚成功。

游戏目录中的 `UserData\BestOffer-rules.json` 保存选择规则，`UserData\BestOffer-settings.json` 保存范围和清货选项。`UserData\BestOffer-last-quote.json` 保存最近一次计算的候选与方案，便于排查。日志在 `MelonLoader\Latest.log`。

## 源码与维护

- `src/BestOffer/BestOfferMod.cs`：报价流程、输入隔离与持久规则。
- `src/BestOffer/NativeTradeUI.cs`：交易 iPad 入口、原生平板页面与单件特征展示。
- `src/BestOffer/ItemRuleGroups.cs`：同名商品组与批量规则接口。
- `src/BestOffer/ItemRuleGroupLogic.cs`：可独立测试的分组、数量与规则保护逻辑。
- `src/BestOffer/GameTradeAdapter.cs`：游戏原生定价、库存、摆放与成交接口。
- `src/BestOffer/OfferSolver.cs`：独立的精确组合求解器。
- `src/BestOffer/TradeOptions.cs`：范围选项与超预算限额换算。
- `tests/Program.cs`：随机穷举对照、预算、种类、必卖禁卖、资源限制与大数测试。
- `tests/ItemRuleGroups.Tests/`：同名数量更新、相反规则保留、容器保护、稳定排序与旧规则兼容测试。
- `docs/` 和 `analysis/`：开发记录与实际测试证据；分析导出与存档不包含在发布包中。
